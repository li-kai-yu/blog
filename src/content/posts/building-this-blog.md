写博客这件事，我断断续续想过很久。直到某天意识到，比起「有没有人看」，更值得问的是：我是否愿意把自己的名字放在这里。

于是有了现在这个站点。它没有复杂的后台，也没有数据库，所有文章都是构建时生成的静态页面。但我想让它看起来、用起来，都像一件被认真对待的作品。

## 为什么还要写博客

信息流越来越快，写长文似乎成了一件低效的事。但我仍然觉得，博客有一个很难被替代的价值：**它是你自己的地盘**。

排版、节奏、语气、放什么不放什么，全部由你决定。你不需要为了平台的推荐机制去拆解标题，也不需要把一段完整的思考切成一屏一屏的碎片。文章可以慢慢展开，读者可以慢慢读完。

这种「慢」，在今天反而变成了一种奢侈。

## 从一块暖色画布开始

我给自己定了几个关键词：温和、克制、有呼吸感。

具体落到设计上，是用暖白作为底色，而不是纯白；用低饱和的墨绿和陶土色做点缀，而不是高对比的霓虹色；用大量留白让信息自己找到位置，而不是靠卡片和分割线把页面填满。

字体也做了取舍。正文使用系统无衬线字体，保证中文阅读的清晰度；英文标题和装饰性文字使用衬线斜体，给页面增加一点书籍感。两种气质混在一起，恰好是我想表达的「工程与温度」。

> 一个好的界面，不应该让人先注意到界面本身。

为了让主题切换不突兀，我把颜色全部收进 CSS 自定义属性，并给深色模式单独准备了一套更柔和的色值。页面首次加载时，会用一小段内联脚本读取系统偏好，避免出现「先闪一下白屏再变黑」的尴尬。

## 动效应该服务于阅读

我很少为了「看起来很酷」而加动效。这个站点里的动效只有三类：

1. **出现**：内容进入视口时轻轻上浮，提示层级关系。
2. **反馈**：链接、按钮、卡片在悬停时给出明确回应。
3. **过渡**：页面切换时短暂淡入，降低跳转的割裂感。

它们都有一个共同点：短、轻、不打断阅读。

实现上也没有引入动画库。进入视口用 `IntersectionObserver`，过渡只改 `transform` 和 `opacity`，让浏览器可以走合成层。

```css
.reveal {
  opacity: 0;
  transform: translateY(24px);
  transition:
    opacity 0.8s cubic-bezier(0.22, 1, 0.36, 1),
    transform 0.8s cubic-bezier(0.22, 1, 0.36, 1);
}

.reveal.is-visible {
  opacity: 1;
  transform: none;
}
```

这套写法简单，却足够稳定。动画库解决的是复杂编排问题，而这个站点暂时不需要那种复杂度。

## 泡泡实验室：一点无用但有趣的东西

如果整个博客都是文章，会显得太严肃。我希望有一个地方，可以放下「有用」的包袱。

于是有了「泡泡实验室」。它是一片会回应鼠标的泡泡场：泡泡会缓慢漂浮，也会在你靠近时轻轻躲开。点击小泡泡会得到一句与技术有关的短句，点击大泡泡则会打开一局小游戏。

三款游戏都刻意做得短：记忆配对、色感挑战、反应测试。目标不是让人上瘾，而是在读文章读累的时候，提供一个两分钟的小憩。

它们全部由原生 DOM、CSS 和 `requestAnimationFrame` 实现，没有引入游戏引擎。物理也只是很简单的东西：一个偏移量、一点弹簧回弹、一个鼠标斥力。但调好参数之后，手感会比想象中更柔和。

## 技术选择与取舍

这个站点的技术栈很普通：

- **React + Vite**：组件化和构建速度都够用。
- **Markdown**：文章以纯文本保存，迁移成本最低。
- **CSS 自定义属性**：主题、间距、字体统一管理。
- **无后端**：构建后就是一组静态文件，可以直接部署到任意静态托管平台。

普通并不意味着简单。真正花时间的，是那些不会被截图记录下来的细节：滚动条出现时布局是否跳动、移动端菜单打开时背景是否还能滚动、深色模式下的边框是否还看得清。

这些细节没有捷径，只能一个页面一个页面地看。

## 写在最后

我仍然不觉得这是一个「完成」的作品。文章会继续写，泡泡的参数可能还会调，某些页面的间距也许明天就会被改掉。

但至少现在，它是一个我愿意分享出去的地址。

如果你读到了这里，谢谢你愿意慢下来。
