上册结束那天，我以为自己已经学完了 Java。直到下册结束，才慢慢意识到，那只是刚认识它。

基础阶段最容易产生一种错觉：视频看完了，代码也跟着敲了，好像就会了。可真正到了项目里，才发现很多概念只是「有印象」，并没有变成能调用的判断。这篇文章想留下些真正带走的东西，而不是一份目录。

## 上册：语法和面向对象的地基

上册覆盖变量、运算符、流程控制、数组、方法、类和对象、继承、接口、异常这些内容。它的节奏不快，但信息密度并不低。

当时的感受是「都能听懂」。变量是什么、循环怎么写、方法怎么传参，这些没有太大障碍。真正让我卡住的是面向对象，尤其是为什么要封装。

我曾把字段都设成 public，程序照样能跑。直到后面改一个需求，发现同一个字段在十几个地方被直接赋值，才明白封装的价值不是防止报错，而是把变化收进一个口子。

### 面向对象真正理解的那一刻

封装、继承、多态，教材上的定义都很短，短到很容易背下来，也很容易忘掉。

我真正理解多态，是在写一个支付场景的练习时。父类定义 pay 方法，微信和支付宝各自实现，调用方只依赖父类。那一刻我才明白，多态不是为了少写几个 if，而是让调用方不必知道具体是谁在干活。

接口也是类似。它不只是一个「更抽象的类」，而是一份约定。谁实现它，谁就要承担这些行为。后面学 Spring 时，这种「面向接口编程」的思路几乎无处不在。

## 下册：从会用 API 到理解机制

下册的难度明显上升。集合、IO、多线程、网络编程、反射、注解，每一块都能单独写一本书。

我对下册的整体感受是：它不再教你怎么写代码，而是开始解释代码为什么这样运行。

### 集合框架：不要一上来就死磕源码

ArrayList 和 HashMap 大概是所有教程都会讲源码的两个类。我一开始也尝试逐行读，结果很快就放弃了。

后来我换了个方法：先记住它们的结构特征。ArrayList 底层是数组，查询快、中间插入慢；HashMap 是数组加链表，后来引入红黑树，靠哈希定位桶。知道这些之后，再去理解扩容、负载因子、哈希冲突，就顺了很多。

源码当然值得读，但不必在第一次接触时读。先建立结构感，再用问题去驱动源码，效率会高很多。

### IO、多线程、网络编程的定位

这三块内容在当时看起来离业务很远，实际上决定了后面能不能理解框架。

IO 让我知道数据是怎么在程序和文件、网络之间流动的；多线程让我第一次接触共享状态和锁；网络编程则把 HTTP 请求还原成了字节流。后来回头看 Spring 的线程模型、连接池、异步处理，很多底层假设都来自这里。

### 反射与注解：框架的入口

反射是下册里最让我意外的一节。原来一个类可以在运行时被加载、被创建、被调用方法。

注解则是另一面。它本身不做任何事，只是一段元数据，真正让它生效的是读取注解的代码。理解这一点后，再去看 Spring 的 @Autowired、@RequestMapping，就不再觉得它们是魔法。

## 一个排序练习

集合部分我做得最多的练习，是用 Comparator 排序。它很小，但把泛型、函数式接口和链式调用串在了一起。

```java
List<Order> orders = new ArrayList<>();
orders.add(new Order("A001", 128));
orders.add(new Order("A002", 76));
orders.add(new Order("A003", 210));

// 按金额从高到低排，金额相同再按编号升序
orders.sort(
    Comparator.comparingInt(Order::getAmount).reversed()
              .thenComparing(Order::getNo)
);

for (Order order : orders) {
    System.out.println(order.getNo() + " " + order.getAmount());
}
```

写完之后我才发现，Comparator 不只是「比较器」，它把排序规则从数据里抽了出来，变成可以组合的对象。这种思路在后面很多地方都能见到。

## 基础如何影响后面

学 Spring 时，我常有一种似曾相识的感觉。

IOC 容器要创建对象，需要反射；AOP 的动态代理，依赖接口和运行时代理；注解驱动开发，本质是读取元数据。下册那些当时觉得抽象的内容，在这里全部落了地。

做项目时也是一样。集合用得多不多，决定你会不会写出低效的循环；对线程安全有没有概念，决定你会不会在共享状态上踩坑；理解异常体系，决定你的错误处理是清晰还是混乱。

## 给初学者的几句实话

第一，上册不要急着跳。面向对象没想明白，后面的框架只会越学越玄。

第二，下册不要追求一次学透。第一遍建立地图，第二遍再填细节，很正常。

第三，多写小练习，但别只写教程里的。给练习加一点自己的需求，哪怕只是多一个排序条件，理解也会更深。

基础阶段不会带来立竿见影的成就感，它更像是在修一条路。当时看不出用途，后面走得越远，越知道它值不值。
