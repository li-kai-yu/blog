学 Java Web 之前，我对「后端」的理解很模糊：大概就是写接口、连数据库。真正开始学，才发现这中间有一条很长的链路。

这段学习的价值，不在于多学了一个框架，而在于我第一次能完整解释：一个请求从浏览器发出，到最后变成 JSON 返回，中间到底发生了什么。

## 为什么先学 Servlet，再学框架

刚接触 Servlet 时，我也有过疑问：现在都用 Spring Boot 了，为什么还要写这些又长又啰嗦的类。

学完之后我理解了。Servlet 是这条链路的起点，它把 HTTP 请求抽象成对象，交给你的代码处理。Spring MVC 并没有绕开它，只是在这一层之上做了更细的分工。不理解 Servlet，就很难理解 DispatcherServlet、过滤器、请求参数绑定这些概念从哪来。

框架让人写得快，底层让人想得清楚。这两件事不冲突。

## 一次请求在容器里的旅程

浏览器发出请求后，最先到达的是 Web 容器，比如 Tomcat。

容器根据 URL 找到对应的 Servlet，创建请求和响应对象，然后调用 Servlet 的方法。你的代码从请求里取出参数，调用业务逻辑，查数据库，最后把结果写回响应。容器负责连接、线程、协议解析这些脏活，开发者只需要关心中间那段。

理解这一点后，「请求作用域」「会话」「过滤器链」这些词就不再是孤立的知识点，而是同一条链路上的不同位置。

## 生命周期、Filter 与 Listener

Servlet 的生命周期有三个关键点：初始化、服务、销毁。默认情况下，一个 Servlet 实例会被多个请求复用，这也是为什么它不适合存放请求相关的状态。

Filter 则站在 Servlet 之前，可以在请求进入和响应返回时做处理。编码设置、登录校验、日志记录，都适合放在这里。它像一个关卡，请求必须经过它才能继续。

Listener 关注的是应用级别的事件，比如容器启动、会话创建和销毁。它不参与单次请求，但在需要全局初始化时很有用。

这三者放在一起，构成了我对 Web 容器最直观的认识。

## JDBC 的重复与 MyBatis 的抽象

JDBC 是 Java 访问数据库的标准方式。加载驱动、获取连接、创建语句、处理结果集、关闭资源，每一步都很清晰。

问题是太重复。几乎每个查询都要写一遍样板代码，参数和结果集还要手动映射。项目一大，重复就会变成负担。

MyBatis 解决的正是这部分重复。它把 SQL 和 Java 对象之间的映射抽出来，让开发者专注在 SQL 本身。JDBC 并没有消失，只是被藏到了更下面。

我后来养成一个习惯：用 MyBatis 时，仍然会想一下它最终生成的 JDBC 操作大概是什么样。这个习惯帮我排查过不少问题。

## Maven：依赖也需要秩序

在 Maven 之前，我对「依赖」的理解就是把 jar 包复制到 lib 目录。

Maven 把这件事变成了声明。你在 pom 里写下需要什么，它负责下载、传递依赖、管理版本。项目结构也随之统一，编译、测试、打包都有固定的生命周期。

第一次遇到依赖冲突时我很困惑：明明只引入了一个库，为什么多出来一堆 jar。后来才明白，依赖也会传递，版本也需要协调。这是工程化的一部分，不是 Maven 的毛病。

## 第一个 Spring Boot 接口

真正写第一个 Spring Boot 接口时，有种「原来可以这么短」的感觉。

一个 Controller，一个注解，方法返回对象，框架自动序列化成 JSON。启动类跑起来，内嵌的 Tomcat 也跟着起来了。

但短不代表简单。分层很快成为必须面对的问题：Controller 负责接收和返回，Service 负责业务，Mapper 负责数据访问。每一层各管一件事，代码才不会挤在一起。

```java
@RestController
@RequestMapping("/api/orders")
public class OrderController {

    private final OrderService orderService;

    public OrderController(OrderService orderService) {
        this.orderService = orderService;
    }

    @GetMapping("/{id}")
    public Result<OrderVO> get(@PathVariable Long id) {
        return Result.success(orderService.getById(id));
    }
}
```

这段代码很短，但它包含了几个关键点：依赖注入、路由映射、参数绑定、统一返回结构。每一个都可以继续往下挖。

## 前后端分离与 JSON

Java Web 阶段还有一个明显的变化：页面不再由后端渲染。

后端只负责提供接口，返回 JSON；前端自己决定怎么展示。职责分开之后，后端可以更专注地处理数据和业务，接口也更容易被复用。

代价是沟通成本变高。字段命名、状态码、错误结构，都需要提前约定。我吃过不少亏，后来才学会在写接口前先把返回格式定下来。

## 学完之后的变化

最大的变化不是会用了 Spring Boot，而是看请求时有了层次感。

以前看到一个接口，只关心它返回什么；现在会想它经过哪些过滤器、在哪个线程执行、事务从哪里开始、异常在哪里被兜住。这种视角，是 Servlet 和 JDBC 那段时间给的。

框架会一直变，但这条链路短期内不会变。先把它走通，再学框架，心里会踏实很多。
