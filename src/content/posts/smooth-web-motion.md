「丝滑」是一个很主观的词，但它背后有一组相当具体的工程实践。

这篇文章不讨论如何做出炫酷的特效，而是整理那些会让页面「感觉对」的细节。它们大多不起眼，却决定了用户是否愿意多停留一会儿。

## 1. 动效的目的不是炫技

先问一个问题：这个动画在传达什么？

常见的目的无非三类：

- **空间关系**：元素从哪里来，到哪里去。
- **状态变化**：操作成功、失败、加载中。
- **注意力引导**：让用户注意到刚刚发生的变化。

如果一个动画无法回答「它在表达什么」，那它大概率可以删掉。

## 2. 只动 transform 和 opacity

浏览器渲染一帧要经过布局、绘制、合成。改变 `width`、`height`、`top`、`left` 这类属性，可能触发重新布局；改变颜色、阴影，可能触发重绘。

而 `transform` 和 `opacity` 通常只需要合成层参与，代价低得多。

```css
.card {
  transition:
    transform 0.45s cubic-bezier(0.22, 1, 0.36, 1),
    box-shadow 0.45s ease;
}

.card:hover {
  transform: translateY(-4px);
}
```

能用 `transform` 表达的位移、缩放、旋转，就不要用会触发布局的属性。

## 3. 把节奏做对

同样的位移，用不同的缓动曲线，观感差别很大。

- **进入**适合 `ease-out`：快速启动，缓慢停下，像物体被轻轻放下。
- **离开**适合 `ease-in`：缓慢启动，快速消失。
- **原地反馈**适合短促的曲线，不要拖泥带水。

我常用的一条曲线是 `cubic-bezier(0.22, 1, 0.36, 1)`，它有一种「先快后慢」的柔和感，适合大多数界面动效。

时长也很重要。交互反馈通常控制在 150–300ms，页面级过渡可以到 500–800ms。超过一秒的动画，除非有叙事意义，否则很容易让人不耐烦。

## 4. 进入视口的内容，别一次性全出现

列表或卡片一起出现，会显得呆板。给同类元素加一点错峰延迟，节奏会立刻变得自然。

```css
.item {
  opacity: 0;
  transform: translateY(18px);
  transition:
    opacity 0.7s cubic-bezier(0.22, 1, 0.36, 1),
    transform 0.7s cubic-bezier(0.22, 1, 0.36, 1);
}

.item.is-visible {
  opacity: 1;
  transform: none;
}

.item:nth-child(2) { transition-delay: 60ms; }
.item:nth-child(3) { transition-delay: 120ms; }
```

延迟不要太大，60–100ms 的间隔通常就够了。太多会让用户觉得页面在「加载」，而不是「展开」。

## 5. 页面切换需要一点缓冲

单页应用的跳转如果瞬间完成，会有一种「内容被替换」的断裂感。

最简单的做法，是给新页面一个短暂的淡入和轻微上移。它不需要复杂，只要让眼睛有一个过渡的锚点。

如果使用浏览器的 View Transitions API，还可以做出更自然的共享元素过渡。但无论用什么方式，都要记住：过渡是为了降低认知负担，而不是增加等待时间。

## 6. 滚动时，别和用户抢控制权

滚动劫持是很多「炫酷」网站最大的体验问题：用户想往下滑，页面却按自己的节奏走。

我更倾向于尊重系统滚动，只在必要时做轻量增强，例如：

- 滚动进度条；
- 标题在进入视口时淡入；
- 导航在滚动后改变背景。

这些都不改变滚动的物理行为，只是提供额外的信息。

## 7. 尊重用户的系统设置

有些人会因为前庭功能敏感而关闭系统动效。`prefers-reduced-motion` 就是为此准备的。

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

这不是一个可选项。动效应该是加分项，而不是使用门槛。

## 一份自检清单

发布前，我会问自己：

- 动画是否只使用了 `transform` 和 `opacity`？
- 交互反馈是否在 300ms 内完成？
- 列表出现是否有节奏，而不是同时闪现？
- 滚动是否保持原生手感？
- 低性能设备上是否仍然流畅？
- 关闭系统动效后，页面是否仍然可用？

丝滑从来不是某一个特效带来的。它是很多个正确的小决定，叠加出来的整体感受。

而这些决定，往往都藏在用户不会主动注意的地方。
